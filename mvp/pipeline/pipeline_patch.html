    How to read this map

    Each box is one step. A record travels left to right through four sections: 1 Collect, 2 Read, 3 Judge, 4 Record. Click a box for what it does, who or what runs it, what goes in, what comes out and where it is kept.

    The look of a box

    Works today and has been run.
    Built, but not run on real data yet.
    Not built yet: a placeholder.
    Rounded corners: a person does this.
    Turned corner: a document or a folder of files, not an action.
    Heavy right edge: an end point. Records that reach it go no further.

    Run by

    The line at the foot of every box says who or what does the work:

    Script
    A program in mvp/pipeline/run.py, the same every time.
    Model + prompt
    An AI model following written instructions in mvp/prompts/, run from Claude Code with /classify-incidents.
    Fixed rule
    A rule written in code, applied to facts already extracted. No judgement, no model.
    Person
    Somebody reads and decides.
    Document
    A file people write and the pipeline reads.

    The numbers on the boxes

    Every number on the map is a number of records, over all sources. A record is one incident as one source describes it, for example AIID incident 1604 (aiid:1604). Never lines in a file, readings or suggestions: a record read twice, or with two suggestions, still counts once.

    Numbers go where the records go. Each wire carries the number of records that travel along it. At every box, what comes in equals what goes on, plus what stops there, plus what is still waiting there. Click a box to see its number split by source and by the groups that matter there, where it comes from, where it goes and which files it is counted from. If any of these sums fails, a warning above the map lists it.

    A few boxes show something that is not a count of records: the number of sources, the size of the rulebook, a score. Their number is slanted and carries a dotted tag that says what it counts. Where a box shows a word (“rule”) there is nothing to count.

    The numbers are taken from the project's files when this page was made. While an update runs, they are counted again each time a step finishes or waits for you, and the boxes change in place.

    Wires

    Records passed on automatically. The label gives how many.
    Records handed to or from a person.
    The same records, also sent on a side path (naming the pattern). Not part of the box's split.
    A rule or a list is read. No records travel.
    Not built yet.

    Two ways to run it

    Both need the front end: python mvp/pipeline/run.py serve, then open the address it prints.

    Update runs the real pipeline and changes the project's files. While it runs, each box gets a tag: pending running your turn done failed skipped not built yet. “Your turn” means the run is waiting for you; the panel on the right says what to do.

    Test run is a dry run. The same steps run, with the same panel, tags and choices, on a handful of made-up incidents in a scratch folder. Your project's files are not touched and nothing is downloaded. Where a step would wait for Claude Code or for you, Continue puts sample work in place so you can see what happens next; Skip shows what happens without it.

    A test run is marked everywhere it shows: Test run in the panel and the window title, and striped title bars. While its panel is open, the numbers on the boxes are the test run's, counted in its scratch folder: sample figures, not your project's. The window title says so. Close the panel and the boxes show your project's numbers again.
