Evidence index of multi-agent AI risks ·

Multi-agent AI incidents taxonomy mapping

Context. Hammond et al. 2025, Multi-Agent Risks from Advanced AI set out a comprehensive taxonomy of the risks that arise when AI agents interact. It has three failure modes and seven risk factors. As AI agents built on large language models grow more capable, these risks are showing up more often. Several incident trackers already label some incidents as multi-agent. But each one sees only part of the picture, and they label incidents in different ways. What is missing is a tracker with one unified view of multi-agent risk.

Goal. Provide that view. We bring incidents from several sources into one index and map each one onto the Hammond et al. taxonomy. An incident reported by more than one source counts once. We include four kinds of evidence: real-world incidents, simulated environments built by researchers, lab experiments on real models, and theoretical arguments where no AI system was run. The index shows which multi-agent risks have evidence behind them and which have none yet. This is work in progress: this release maps failure modes only, and risk factors come next.

Setup. The AI Incident Database (AIID) is the main source. Every AIID record dated 2024 or later is checked. Older AIID records enter only when flagged. Other sources are added by hand at irregular intervals. A human analyst decides whether each incident is in scope.

§1 · Failure modes

Where the incidents land.

Incidents per failure mode, split by evidence type. The failure mode is derived by rule from the facts read in each source, and each incident has at most one. Incidents whose facts do not settle it are counted apart, not forced into a mode.

§2 · Instances

Which mechanisms show up, by failure mode.

Rows are the instances, in id order. Columns are the incident's failure mode. A cell counts incidents that carry both. Instances are assigned on their own and give an incident no failure mode or risk factor. Hover an instance to see where the paper discusses it.

Fig. 2 Two labels on one incident are a count, not a link. Rows are not grouped by failure mode or risk factor, so no cell reads as a link between the two. Red marks an instance with no incident. Instances marked proposed are not in the paper. This index added them because incidents showed behaviour the paper's Table 1 does not name.

§3 · Time

When they happened.

Incidents in the index by event date, cumulative. Studies are placed at their publication date.

§4 · All incidents

All incidents.

§5 · Method

How an incident gets here.

Every record takes the same path. Scripts move and count data, a model reads sources and writes down facts with quotes, fixed rules turn those facts into labels, and a human analyst makes every decision that puts an incident in the index.
