    How to read this map

    Each box is one step. A record travels left to right through four main sections: 1 Collect, 2 Read, 3 Judge, 4 Record. Two side sections sit beside them: Discover, not built yet, inside Collect; and Test, which checks the rules against an answer key. Click a box for how many records are there right now, where they go, what the step does, who or what runs it and where it is kept.

    The words used everywhere are defined in 0.2/docs/glossary.md. The main ones: a record is one source's account of one incident; a candidate is a record worth reading; a reading is our notes on what a source says, with quotes; a dossier is our own file on one incident; to promote a record is to make a dossier for it. Gate 1 asks whether an incident is multi-agent; Gate 2 asks what kind of failure it shows.

    The look of a box

    Operational: the files it writes hold output.
    Built, but its files hold no output yet.
    Not built yet: a placeholder.
    Rounded corners: a person does this.
    Turned corner: a document or a folder of files, not an action.
    Heavy right edge: an end point. Records that reach it go no further.

    Run by

    The line at the foot of every box says who or what does the work:

    Script
    A program in 0.2/pipeline/run.py, the same every time.
    Model + prompt
    An AI model following written instructions in 0.2/prompts/, run from Claude Code with /classify-incidents.
    Fixed rule
    A rule written in code, applied to facts already extracted. No judgement, no model.
    Person
    Somebody reads and decides.
    Document
    A file people write and the pipeline reads.

    The numbers on the boxes

    Most numbers on the map are numbers of records, over all sources. A record is one source's account of one incident. The same incident can be told by several sources, so it can be several records, and one dossier can list them all. A record counts once however often it was read or how many suggestions it has: the numbers never count lines in a file.

    Numbers go where the records go. Each wire carries the number of records that travel along it. At every box, what comes in equals what goes on, plus what stops there, plus what is still waiting there. Click a box to see its number split by source and by the groups that matter there, where it comes from, where it goes and which files it is counted from. The line above the map says how many of these sums hold; if any fails, it turns into a warning that lists each one.

    The exceptions are the boxes that show something other than records: the number of sources, the size of the Risk Instances Repo, a score. Their number is slanted and carries a dotted tag that says what it counts. Where a box shows a word (“rule”) it has no count of its own.

    The numbers are counted from the project's files by python 0.2/pipeline/run.py index, and the page is drawn from them by run.py viz. The line above the map says when they were counted. While an update runs, they are counted again each time a step finishes or waits for you, and the boxes change in place.

    Wires

    Records passed on automatically. The label gives how many.
    Records handed to or from a person.
    The same records, also sent on a side path (naming the pattern). Not part of the box's split.
    A rule or a list is read. No records travel.
    Not built yet.

    Two ways to run it

    Both can be started from the command line, python 0.2/pipeline/run.py update or run.py testrun, or from this page once python 0.2/pipeline/run.py serve is running: open the address it prints. Only the page shows the tags and the panel with Continue and Skip. On the command line an update stops at a step that needs a person and says what to do; a test run answers every such step itself.

    Update runs the real pipeline and changes the project's files. While it runs, each box gets a tag: pending running your turn done failed skipped not built yet. “Your turn” means the run is waiting for you; the panel on the right says what to do.

    Test run is a dry run. The same steps run, with the same panel, tags and choices, on a handful of made-up incidents in a scratch folder. Your project's files are not touched and nothing is downloaded. Where a step would wait for Claude Code or for you, Continue puts sample work in place so you can see what happens next; Skip shows what happens without it.

    A test run is marked everywhere it shows: Test run in the panel and the window title, and striped title bars. While its panel is open, the numbers on the boxes are the test run's, counted in its scratch folder: sample figures, not your project's. The window title says so. Close the panel and the boxes show your project's numbers again.
